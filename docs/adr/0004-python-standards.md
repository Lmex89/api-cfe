# Python standards with a shrinking baseline

We use Ruff for lint, import ordering, Google-style docstrings, complexity and formatting, and mypy for types, rather than separate overlapping tools. Dev-only pinned dependencies and local pre-commit hooks keep production dependencies and deployment unchanged. Frozen diagnostic and formatting-edit counts grandfather existing violations without suppressing whole rules or files. Contributors remove resolved entries from the baseline as they fix them; this avoids a mass rewrite. Mypy uses strict mode but ignores missing imports. Identical violations exchanged within a file cannot be distinguished by the baseline. Local hooks are bypassable and are not CI enforcement. Automated limits cannot guarantee sound SOLID design or English docstrings.

Mypy checks tracked Python files across the repository in an isolated copy, with explicitly selected files included; this prevents unrelated untracked files from changing import resolution or blocking commits. Pre-commit supplies staged contents during commits. Baseline paths do not follow renames automatically, so existing entries must be reviewed and moved or the violations fixed.
